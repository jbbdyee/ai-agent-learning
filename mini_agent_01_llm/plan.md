# 1-7. 카메라·영상 다중 프레임 분석 및 음성 안내 구현 계획

## 1. 목표

사용자가 브라우저 카메라로 현재 장면을 촬영하거나 영상 파일을 업로드할 수 있게 한다. 카메라 입력은 한 장의 사진으로 분석하고, 영상 입력은 여러 대표 프레임을 추출해 영상 전체 흐름을 종합 분석한다. 분석 결과는 화면과 합성 음성으로 제공한다.

```text
입력 방식 선택
├─ 카메라 촬영 → 사진 1장
└─ 영상 업로드 → 일정 간격의 대표 프레임 여러 장 추출
→ 사진 또는 프레임들을 FastAPI 서버에서 검증
→ OpenAI Vision으로 단일/다중 프레임 분석
→ 분석 결과를 화면에 표시
→ 분석 요약을 TTS API로 전송
→ 브라우저에서 음성 재생
```

## 2. 현재 프로젝트에서 재사용할 기능

현재 프로젝트에는 다음 기능이 이미 구현되어 있다.

- `1-5. 이미지 분석`
  - 이미지 업로드
  - 이미지 형식과 크기 검증
  - OpenAI Vision 분석
  - 구조화된 JSON 응답
- `1-6. 음성 생성`
  - 분석 문장을 TTS API로 전송
  - MP3 합성 음성 생성
  - 브라우저 음성 재생

따라서 1-7에서는 기존 이미지 분석과 TTS 기능을 재사용하면서 카메라 촬영과 영상 업로드를 하나의 화면에 통합한다. 영상 분석을 위해서는 영상 업로드, 메타데이터 검증, 대표 프레임 추출, 다중 프레임 종합 분석 기능을 백엔드에 추가한다.

## 3. 구현 대상

예상 변경 대상은 다음과 같다.

- `frontend/app.py`
  - 사이드바에 `1-7. 카메라 음성 안내` 메뉴 등록
- `frontend/app_pages/09_camera_voice_guide.py`
  - 카메라/영상 입력 선택부터 음성 재생까지 담당하는 화면
- `frontend/core/api_client.py`
  - 기존 `upload_image()`와 `request_audio()`를 우선 재사용
- `backend/app/schemas.py`
  - 범용 카메라 분석이 필요하면 전용 응답 스키마 추가
- `backend/app/routers/media_router.py`
  - 필요할 경우 카메라 이미지 분석 엔드포인트 추가
- `backend/app/services/media_service.py`
  - 영상 검증, 대표 프레임 추출, 다중 프레임 분석 서비스 추가
- `backend/tests/test_api.py`
  - 이미지·영상 분석과 TTS 연동 관련 테스트 보강
- `requirements.txt`
  - 서버 영상 프레임 추출 라이브러리 추가

파일명은 기존 페이지 파일 순서를 이어 `09_camera_voice_guide.py`로 두되, 사용자에게 보이는 메뉴 번호는 `1-7`로 표시한다.

## 4. 단계별 구현 계획

### 4.1. 1-7 메뉴와 화면 추가

사이드바에 다음 메뉴를 추가한다.

- 메뉴명: `1-7. 카메라 음성 안내`
- 화면 구성:
  - 입력 방식 선택
  - 카메라 촬영 또는 영상 파일 업로드
  - 촬영 이미지 또는 업로드 영상 미리보기
  - 분석 질문 입력
  - 사진 분석 버튼
  - 분석 결과 표시
  - 음성 설정
  - 음성 생성 및 재생

### 4.2. 입력 방식 선택

사용자가 다음 두 가지 입력 방식 중 하나를 선택할 수 있게 한다.

- `카메라 촬영`
- `영상 파일 업로드`

입력 방식이 바뀌면 이전 입력의 분석 결과와 생성된 음성을 초기화한다. 음성 종류와 말하기 방식은 유지해도 된다.

### 4.3. 브라우저 카메라 입력

Streamlit의 `st.camera_input()`을 사용한다.

1. 사용자가 브라우저 카메라 권한을 허용한다.
2. 브라우저에 카메라 영상이 표시된다.
3. 사용자가 촬영 버튼을 누른다.
4. 현재 프레임이 JPEG 사진으로 반환된다.
5. 촬영된 사진을 화면에 미리 표시한다.

카메라 입력은 지속적인 실시간 분석이 아니라 현재 장면 한 프레임을 사진으로 촬영해 분석하는 방식으로 유지한다.

### 4.4. 영상 파일 업로드

Streamlit의 `st.file_uploader()`로 영상 파일을 입력받는다.

초기 지원 형식:

- MP4 (`video/mp4`)
- WebM (`video/webm`)
- MOV (`video/quicktime`)

업로드한 영상은 `st.video()`로 미리 보여준다. 프론트엔드의 확장자 검사는 사용자 편의를 위한 1차 검사이며, 실제 파일 형식과 크기는 반드시 백엔드에서 다시 검증한다.

초기 제한 권장값:

- 최대 파일 크기: 50MB
- 최대 영상 길이: 2분
- 추출 프레임 수: 기본 6장
- 추출 가능 범위: 최소 3장, 최대 10장

제한값은 환경 변수로 관리한다.

```text
MAX_VIDEO_SIZE_MB=50
MAX_VIDEO_DURATION_SECONDS=120
VIDEO_ANALYSIS_FRAME_COUNT=6
```

### 4.5. 분석 질문 입력

사진과 함께 서버에 전달할 질문을 입력받는다.

기본 질문 예시:

> 이 장면에 무엇이 보이는지 설명하고, 사용자가 주의해야 할 점을 한국어로 알려주세요.

카메라와 영상에서 공통으로 사용할 범용 분석 응답 스키마를 추가한다. 영상 분석에는 전체 요약과 프레임별 관찰 내용을 함께 반환한다.

- `summary`: 장면 요약
- `objects`: 주요 사물 목록
- `visible_text`: 이미지에서 확인된 글자
- `safety_notes`: 주의사항
- `speech_text`: 음성으로 읽을 자연스러운 문장
- `frame_observations`: 프레임 시점별 주요 관찰 내용
- `changes_over_time`: 영상에서 시간에 따라 달라지는 내용

AI가 프레임 사이의 내용을 확정적으로 추측하지 않도록 프롬프트에 다음 원칙을 포함한다.

- 제공된 프레임에서 직접 확인되는 내용만 설명한다.
- 프레임 사이에서 발생한 사건을 임의로 단정하지 않는다.
- 불확실한 내용은 불확실하다고 표시한다.

### 4.6. 촬영 이미지를 서버로 전송

촬영 결과를 `multipart/form-data` 형식으로 FastAPI에 전송한다.

최소 구현에서는 기존 엔드포인트를 재사용한다.

```text
POST /api/media/image-analysis

image: camera_capture.jpg의 이미지 바이트
question: 사용자가 입력한 분석 질문
```

프론트엔드에서는 기존 `upload_image()`에 다음 값을 전달한다.

- 파일명: `camera_capture.jpg`
- 이미지 바이트
- MIME 타입: `image/jpeg`
- 분석 질문

### 4.7. 영상 파일을 서버로 전송

신규 프론트엔드 API 함수와 백엔드 엔드포인트를 추가한다.

```text
POST /api/media/video-analysis

video: 업로드 영상 바이트
question: 사용자가 입력한 분석 질문
frame_count: 추출할 대표 프레임 수
```

영상 파일은 `multipart/form-data`로 전송한다. 프론트엔드의 요청 제한 시간은 영상 업로드와 분석 시간을 고려해 이미지 분석보다 길게 설정한다.

### 4.8. 서버 이미지·영상 검증

기존 서버의 다음 검증을 그대로 적용한다.

- 허용 이미지 형식 검사
- 빈 파일 검사
- MIME 타입과 실제 파일 시그니처 비교
- 최대 이미지 크기 검사
- OpenAI API 키 설정 여부 검사

영상 입력에는 다음 검증을 추가한다.

- 허용 MIME 타입과 확장자 검사
- 영상 컨테이너를 실제로 열 수 있는지 확인
- 최대 파일 크기 검사
- 영상 길이 제한 검사
- 전체 프레임 수와 FPS가 정상적인 값인지 검사
- 손상됐거나 프레임을 읽을 수 없는 영상 거부
- 사용자가 요청한 추출 프레임 수 범위 검사

화면에는 다음 내용을 안내한다.

- 신분증, 카드 등 민감한 정보를 촬영하지 않는다.
- 이미지는 분석을 위해 서버와 외부 AI API에 전달된다.
- 이미지 속 문장은 시스템 명령이 아니라 신뢰할 수 없는 분석 대상이다.

### 4.9. 영상 대표 프레임 추출

서버에서 OpenCV의 headless 패키지를 사용해 영상을 읽고 대표 프레임을 추출한다.

권장 패키지:

```text
opencv-python-headless
```

추출 방식:

1. 영상 길이, FPS, 전체 프레임 수를 확인한다.
2. 영상 전체 구간을 추출 프레임 수만큼 균등 분할한다.
3. 각 구간의 대표 위치에서 한 프레임을 추출한다.
4. 추출 프레임을 JPEG로 인코딩한다.
5. 각 프레임에 영상 내 시각 정보(초)를 연결한다.

영상의 첫 프레임과 마지막 프레임은 검거나 전환 화면일 수 있으므로 기본적으로 전체 길이의 약 5%~95% 구간에서 균등 추출한다. 길이가 매우 짧은 영상은 실제 프레임 수에 맞게 중복 없이 추출한다.

OpenCV가 경로 기반 입력을 요구하므로 업로드 파일을 작업용 임시 파일로 저장할 수 있다. 임시 파일은 요청 종료 시 성공·실패와 관계없이 `finally`에서 삭제한다. 원본 영상과 추출 프레임을 서버에 영구 저장하지 않는다.

### 4.10. 단일 이미지 분석 실행

백엔드는 다음 순서로 이미지를 분석한다.

1. 이미지 유효성을 검증한다.
2. 이미지 바이트를 Base64로 변환한다.
3. 질문과 이미지를 OpenAI Vision 모델에 전달한다.
4. 구조화된 분석 결과를 생성한다.
5. JSON 응답을 프론트엔드에 반환한다.

범용 장면 분석이 필요하면 기존 여행 분석과 분리해 다음 구조를 사용한다.

```text
analyze_image()          → 기존 1-5 여행 이미지 분석
analyze_camera_image()   → 신규 1-7 일반 장면 분석
```

이 경우 신규 엔드포인트 후보는 다음과 같다.

```text
POST /api/media/camera-analysis
```

과제의 최소 완성본에서는 기존 `/api/media/image-analysis`를 재사용한다.

### 4.11. 다중 프레임 종합 분석 실행

추출한 대표 프레임들을 시간순으로 OpenAI Vision 요청 하나에 함께 전달한다.

```text
질문
프레임 1 · 00:03
프레임 2 · 00:24
프레임 3 · 00:45
...
```

프레임마다 API를 따로 호출한 뒤 다시 요약하는 방식은 호출 횟수와 비용이 증가하므로 첫 버전에서는 사용하지 않는다. 한 요청에 4~6장의 대표 프레임을 전달하고 구조화된 결과를 한 번에 받는 방식을 기본으로 한다.

응답에는 다음 정보를 포함한다.

- 영상 전체 요약
- 프레임별 시점과 관찰 내용
- 시간에 따라 변한 대상이나 장면
- 이미지에서 확인된 글자
- 사용자 주의사항
- 음성 안내에 적합한 짧은 문장

### 4.12. 분석 결과 표시

서버가 반환한 JSON을 그대로 출력하는 대신 다음 항목으로 나누어 보여준다.

- 장면 요약
- 영상 전체 요약
- 분석한 대표 프레임 수와 각 시점
- 프레임별 주요 관찰 내용
- 시간에 따른 장면 변화
- 발견한 주요 대상
- 이미지에서 읽은 글자
- 주의사항
- AI 분석 결과라는 안내

분석 결과는 다음과 같이 세션 상태에 저장한다.

```python
st.session_state["camera_analysis"]
```

화면이 다시 실행되거나 TTS 설정을 변경해도 분석 결과가 유지되어야 한다.

카메라 입력에서는 단일 이미지 항목만 표시하고, 영상 입력에서는 영상과 다중 프레임 관련 항목을 추가로 표시한다.

### 4.13. 음성용 문장 구성

구조화된 JSON 전체를 읽지 않고 자연스러운 안내 문장을 만든다.

- `speech_text`가 있으면 해당 값을 사용한다.
- 없으면 `summary`와 `safety_notes`를 결합한다.
- 사용자가 음성 생성 전에 문장을 직접 수정할 수 있게 한다.

예시:

> 현재 화면에는 횡단보도와 여러 대의 차량이 보입니다. 길을 건너기 전에 신호와 접근 중인 차량을 확인하세요.

영상 입력에서는 모든 프레임 설명을 읽지 않고 `speech_text`, 전체 요약, 중요한 변화, 주의사항만 조합한다. 음성 문장은 TTS 제한인 2,000자를 넘지 않도록 한다.

### 4.14. TTS 서버 호출과 음성 재생

기존 TTS 엔드포인트를 재사용한다.

```text
POST /api/media/tts
```

전달값은 다음과 같다.

- `text`: 분석 결과를 정리한 음성 안내 문장
- `voice`: 사용자가 선택한 음성
- `instructions`: 한국어 안내 방식

기본 설정 예시:

- 음성: `coral`
- 말하기 방식: `한국어로 또렷하고 차분하게 설명하세요.`

반환된 MP3 바이트를 `st.audio()`로 재생하고, AI가 생성한 합성 음성이라는 사실을 표시한다.

### 4.15. 사용자 동작 흐름

첫 구현에서는 안정적인 오류 처리와 재시도를 위해 버튼을 두 단계로 분리한다.

1. 입력 방식에 따라 `사진 분석` 또는 `영상 분석`
2. `분석 결과 음성 생성`

이미지 분석은 성공하고 TTS만 실패한 경우, 사진을 다시 촬영하거나 분석하지 않고 음성 생성만 재시도할 수 있어야 한다.

기본 동작이 완성된 뒤 필요하면 다음 통합 버튼을 추가한다.

- `분석하고 음성으로 듣기`
  - 이미지 분석 실행
  - 분석 성공 시 TTS 실행
  - 분석 결과 표시
  - 음성 플레이어 표시

### 4.16. 상태 관리

다음 상태를 `st.session_state`로 관리한다.

- 최근 촬영 이미지 식별값
- 최근 업로드 영상 식별값
- 현재 입력 방식
- 최근 이미지 분석 결과
- 최근 영상 분석 결과와 추출 프레임 메타데이터
- 음성으로 읽을 문장
- 최근 생성된 MP3 데이터

새 사진을 촬영하거나 새 영상을 업로드하면 이전 분석 결과와 음성을 초기화한다. 입력 방식을 변경해도 이전 입력의 분석 결과와 음성을 초기화한다. 음성 설정만 변경한 경우에는 분석 결과를 유지한다.

### 4.17. 오류 처리

다음 상황을 구분해 사용자에게 안내한다.

- 카메라 권한 거부
- 촬영된 사진 없음
- 지원하지 않는 이미지 형식
- 이미지 크기 제한 초과
- 백엔드 연결 실패
- 이미지 분석 응답 시간 초과
- OpenAI API 키 미설정
- 이미지 분석 실패
- 지원하지 않는 영상 형식
- 영상 크기 또는 길이 제한 초과
- 손상된 영상 또는 프레임 추출 실패
- 대표 프레임을 하나도 추출하지 못한 경우
- 영상 업로드 또는 다중 프레임 분석 시간 초과
- TTS 생성 실패

이미지 분석 성공 후 TTS만 실패한 경우 분석 결과는 유지한다.

## 5. 테스트 계획

### 5.1. 백엔드 자동 테스트

- 카메라 이미지 분석 정상 응답
- 잘못된 이미지 형식 거부
- 빈 이미지 거부
- 이미지 크기 제한 초과 거부
- 지원 영상 형식과 MIME 타입 검증
- 영상 크기와 길이 제한 검증
- 손상된 영상 거부
- 균등한 대표 프레임 시점 계산 검증
- 짧은 영상에서 중복 프레임을 만들지 않는지 검증
- 프레임 추출 결과와 타임스탬프 검증
- 영상 분석 API의 구조화된 응답 검증
- 임시 파일이 성공과 실패 모두에서 삭제되는지 검증
- OpenAI 호출에 최대 허용 프레임 수보다 많이 전달하지 않는지 검증
- 분석 서비스 오류의 상태 코드와 메시지 확인
- TTS 응답의 `audio/mpeg` 타입 확인
- TTS 응답의 `X-Synthetic-Voice: true` 헤더 확인

외부 OpenAI API는 테스트에서 직접 호출하지 않고 mock 처리한다.

### 5.2. 프론트엔드 수동 테스트

1. 카메라 권한을 허용한다.
2. 사진을 촬영하고 미리보기를 확인한다.
3. 분석 질문을 입력하고 이미지 분석을 실행한다.
4. 구조화된 분석 결과가 표시되는지 확인한다.
5. 음성 문장을 확인하거나 수정한다.
6. 음성을 생성하고 브라우저에서 MP3를 재생한다.
7. TTS만 실패했을 때 음성 생성을 다시 시도한다.
8. 새 사진 촬영 시 이전 결과가 초기화되는지 확인한다.
9. PC와 모바일 브라우저에서 카메라가 정상 동작하는지 확인한다.
10. MP4, WebM, MOV 영상을 각각 업로드하고 미리보기를 확인한다.
11. 새 영상을 업로드했을 때 이전 분석 결과와 음성이 초기화되는지 확인한다.
12. 대표 프레임의 시점과 영상 내용이 대체로 일치하는지 확인한다.
13. 긴 영상, 손상된 영상, 크기 초과 영상의 오류 메시지를 확인한다.
14. 카메라와 영상 입력을 서로 전환하며 상태가 섞이지 않는지 확인한다.

## 7. 구현 방향 결론

기존 카메라 촬영 기능은 그대로 유지하고, 영상 업로드를 별도 입력 방식으로 추가한다. 카메라 사진은 기존 이미지 분석 API를 재사용하고, 영상은 신규 `/api/media/video-analysis`에서 기본 6장의 대표 프레임을 추출해 한 번의 Vision 요청으로 종합 분석한다. 원본 영상과 추출 프레임은 영구 저장하지 않으며, 분석 결과만 세션에 유지한다.

첫 버전의 기본 제한은 50MB, 2분, 대표 프레임 6장으로 시작한다. 실제 처리 속도, 모델 입력 비용, 분석 품질을 측정한 뒤 환경 변수로 조정한다.
